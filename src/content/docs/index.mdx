## Why ZKite?

<CardGrid stagger>
  <Card title="100% Native Rendering" icon="seti:android">
    No WebViews, Electron wrappers, or browser DOM. ZKite draws interfaces directly through Android's high-performance native canvas and UI subsystem.
  </Card>
  <Card title="Instant Hot Reload" icon="rocket">
    Iterate at the speed of thought. Edit your Python source files on your computer and see updates appear immediately on your connected physical Android phone or emulator.
  </Card>
  <Card title="Declarative Python UI" icon="seti:python">
    Write familiar, elegant Python. Compose your screens using intuitive layout widgets (`Column`, `Row`, `Grid`, `Stack`) and reactive application state stores.
  </Card>
  <Card title="Production APK & AAB Ready" icon="document">
    Package self-contained release builds (`.apk` and `.aab`) signed with standard Android release keys. End-users install a normal app—they don't need Python or pip.
  </Card>
</CardGrid>

## How Is ZKite Different?

Every developer asks: *"Why not Kivy, BeeWare, Flet, or Chaquopy?"* Here is how ZKite takes a fundamentally different engineering path:

<CardGrid>
  <Card title="vs Kivy (OpenGL Canvas)" icon="seti:python">
    <span class="compare-tag">Architecture: Native Views vs Canvas Imitation</span>
    <div class="compare-section">
      <span class="compare-label">The Kivy Approach</span>
      Kivy paints non-native widgets onto a custom OpenGL surface using Cython and Buildozer recipes. It requires Android NDK toolchains on your PC and lacks genuine Android text selection, platform accessibility, and hardware view physics.
    </div>
    <div class="compare-section">
      <span class="compare-label">The ZKite Advantage</span>
      <strong>100% genuine Android Native Views</strong>. Real text selection, system bars, native touch gestures, and 60/120 FPS frame pacing—with <strong>zero NDK or C++ compilers</strong> on your computer.
    </div>
  </Card>

  <Card title="vs BeeWare (Toga / Briefcase)" icon="seti:java">
    <span class="compare-tag">Tooling: Zero Gradle vs Heavy Android Studio</span>
    <div class="compare-section">
      <span class="compare-label">The BeeWare Approach</span>
      BeeWare uses Rubicon-Java to bridge Python to native widgets, but still requires the full 10+ GB Android Studio, Java SDK, and Gradle daemon build pipelines on your machine for every run.
    </div>
    <div class="compare-section">
      <span class="compare-label">The ZKite Advantage</span>
      <strong>Zero Gradle and zero Java setup</strong> for development. ZKite bundles a pre-built native Android runtime engine and synchronizes code changes in <strong>&lt; 90ms over ADB</strong>.
    </div>
  </Card>

  <Card title="vs Flet (Flutter / Dart VM)" icon="puzzle">
    <span class="compare-tag">Footprint: Single Engine vs Multi-VM Wrapper</span>
    <div class="compare-section">
      <span class="compare-label">The Flet Approach</span>
      Flet wraps Google Flutter by running Python alongside the full Flutter C++ engine and Dart VM, communicating over WebSockets or local IPC. This results in heavy binary size and high RAM consumption.
    </div>
    <div class="compare-section">
      <span class="compare-label">The ZKite Advantage</span>
      <strong>No Flutter, no Dart VM, and no IPC bridge</strong>. A single, unified native Android engine engineered specifically for Python declarative state and layout.
    </div>
  </Card>

  <Card title="vs Chaquopy (Embedded SDK)" icon="seti:android">
    <span class="compare-tag">Paradigm: Python-First vs Java/Kotlin Project</span>
    <div class="compare-section">
      <span class="compare-label">The Chaquopy Approach</span>
      Chaquopy is an embedding plugin for existing Java/Kotlin Android Studio projects. You must still write Gradle configs, Java/Kotlin scaffolding, and JNI bindings to call Python functions.
    </div>
    <div class="compare-section">
      <span class="compare-label">The ZKite Advantage</span>
      A <strong>standalone, Python-first mobile framework</strong>. You write 100% pure declarative Python screens with built-in reactive stores—no Java, Kotlin, or Gradle required.
    </div>
  </Card>
</CardGrid>

## Quick Start in 60 Seconds

```bash
# 1. Install ZKite in an isolated environment
pip install zkite==1.0.0

# 2. Scaffold a new Android application
zkite new my_mobile_app
cd my_mobile_app

# 3. Connect your Android phone and start hot reload
zkite dev
```
